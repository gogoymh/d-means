# 한국어 윤문 가이드

에이전트가 쓰는 한국어 글에서 기계가 번역한 듯한 표현과 종결어미 불일치를 없애는 기준입니다.

## 적용 범위와 원칙

- **적용 대상**: `#general` 메시지, 이슈 제목과 본문, 댓글, 완료 기준, 작업 요약처럼 사용자가 읽는 한국어 글에 적용합니다.
- **영어 문서 유지**: 저장소의 `README.md`, 코드 주석, 커밋 메시지는 `CLAUDE.local.md` 규칙대로 영어로 씁니다.
- **원래 뜻 유지**: 파일 이름, 명령어, 티켓 번호, 실제 동작과 사실은 바꾸지 않고 표현만 자연스럽게 다듬습니다.
- **종결어미 통일**: 한 글 안에서 말투를 하나로 맞춥니다. 채널 메시지, 댓글, 작업 요약은 합쇼체(`~합니다`, `~했습니다`)로 쓰고, 완료 기준이나 항목 목록은 평서체(`~한다`)로 통일합니다.

## DM-22와 DM-25에서 나온 패턴과 고친 예

### 1. 무생물 주어 '~이 ~를 보여 준다'

영어의 `X shows Y`를 그대로 옮겨 화면이나 파일 같은 무생물을 행위 주체로 세우지 않습니다. 화면에 무엇이 나타나는지 자연스러운 한국어 술어로 바꿉니다.

- 원문 (DM-25): `README 첫 화면이 구슬로 된 D 배너를 보여 준다.`
- 고친 예: `README 첫 화면에 구슬로 된 D 배너가 나옵니다.`
- 원문 (DM-26): `구슬 배너 히어로는 워드마크 'D-means'만 보여 준다.`
- 고친 예: `구슬 배너 히어로에는 워드마크 'D-means'만 나옵니다.`

### 2. 영어 직역투 '범위가 잘린 티켓'

`cut-scope`나 `trimmed scope`를 직역하면 한국어에서 쓰지 않는 조합이 됩니다. 문맥에 맞게 범위가 줄었는지 제외됐는지 드러나게 씁니다.

- 원문 (DM-22): `결제·계정·결정이 필요하거나 범위가 잘린 티켓은 건너뛰고`
- 고친 예: `결제, 계정, 결정이 필요하거나 범위가 줄어든 티켓은 건너뛰고`
- 참고: 작업 범위에서 아예 제외된 티켓이라면 `범위에서 빠진 티켓`으로 씁니다.

### 3. 영어 직역투 '가장 분명한 작은 일'

`the clearest small task`를 단어 그대로 옮기면 무엇이 분명하다는 뜻인지 모호합니다. 지금 바로 끝낼 수 있는 작업이라는 뜻을 직접 씁니다.

- 원문 (DM-22): `코드만으로 끝낼 수 있는 배너 미리보기가 지금 가장 분명한 작은 일이다.`
- 고친 예: `코드만으로 끝낼 수 있는 배너 미리보기가 지금 바로 처리할 수 있는 작업입니다.`

### 4. 어색한 외래어 명사구 '배너 렌더'

`banner render`를 그대로 들여오면 렌더링 코드인지 결과 이미지인지 흐려집니다. 실제 대상을 가리키는 말로 바꿉니다.

- 원문 (DM-25): `방금 머지된 배너 렌더가 README 첫 화면에 아직 안 쓰여, 라이트·다크 히어로로 바로 갈아끼우면 된다.`
- 고친 예: `방금 병합된 배너 이미지가 README 첫 화면에 아직 들어가지 않아, 라이트와 다크 히어로로 바로 바꾸면 됩니다.`

### 5. 한 메시지 안의 존댓말과 반말 혼용

앞 문장을 합쇼체(`~했습니다`)로 시작한 뒤 다음 문장에서 해라체(`~이다`, `~된다`, `~보여 준다`, `~빠졌다`)로 꺾으면 문장을 어색하게 이어 붙인 글처럼 읽힙니다. 한 메시지 안의 종결어미를 하나로 맞추고, 설명하는 대상이 바뀌면 문장을 나눕니다.

- 원문 1 (DM-22):
  `미션 DM-22(으)로 맡았습니다. 결제·계정·결정이 필요하거나 범위가 잘린 티켓은 건너뛰고, 코드만으로 끝낼 수 있는 배너 미리보기가 지금 가장 분명한 작은 일이다.`
- 고친 예 1:
  `미션 DM-22를 맡았습니다. 결제, 계정, 결정이 필요하거나 범위가 줄어든 티켓은 건너뛰었습니다. 코드만으로 끝낼 수 있는 배너 미리보기가 지금 바로 처리할 수 있는 작업입니다.`

- 원문 2 (DM-25):
  `미션 DM-25을(를) 마쳐 병합했습니다: README 첫 화면이 구슬로 된 D 배너를 보여 준다. 밝은 화면은 라이트 PNG, 어두운 화면은 다크 PNG이고, 금속 D 사진 d-means-hero.jpg는 빠졌다.`
- 고친 예 2:
  `미션 DM-25를 마쳐 병합했습니다. README 첫 화면에 구슬로 된 D 배너가 나옵니다. 밝은 화면에는 라이트 PNG, 어두운 화면에는 다크 PNG가 나오며 금속 D 사진 d-means-hero.jpg는 뺐습니다.`

## DM-27, DM-28, DM-31과 채점 문서에서 나온 패턴

### 6. 조사 병기 '을(를)', '(으)로'와 받침에 어긋난 조사

틀에 번호를 끼워 넣는 문장은 `을(를)`, `(으)로`, `은(는)`, `이(가)`처럼 조사를 둘 다 적거나, 받침과 맞지 않는 조사를 붙입니다. 사람이 쓴 글처럼 앞말의 마지막 소리에 맞는 조사 하나만 씁니다.

티켓 번호는 마지막 숫자를 읽는 소리로 고릅니다.

| 마지막 소리 | 숫자 | 을/를 | 은/는 | 이/가 | 으로/로 |
|:--|:--|:--|:--|:--|:--|
| 받침 없음 | 2(이), 4(사), 5(오), 9(구) | 를 | 는 | 가 | 로 |
| ㄹ 받침 | 1(일), 7(칠), 8(팔) | 을 | 은 | 이 | 로 |
| 그 밖의 받침 | 0(영), 3(삼), 6(육), 10(십) | 을 | 은 | 이 | 으로 |

- 원문 (judge, DM-27): `미션 DM-27을(를) 마쳐 병합했습니다`
- 고친 예: `미션 DM-27을 마쳐 병합했습니다`
- 원문 (vanguard, DM-22): `미션 DM-22(으)로 맡았습니다.`
- 고친 예: `미션 DM-22를 맡았습니다.`
- 원문 (polish, DM-30): `미션 DM-30(으)로 맡았습니다.`
- 고친 예: `미션 DM-30을 맡았습니다.`
- 원문 (미션 안내): `DM-30의 내부 번호 21을(를) 넣으세요.`
- 고친 예: `DM-30의 내부 번호 21을 넣으세요.`
- 원문 (Claude 287D, DM-15): `DM-15은 끝났고, 이제 d-means의 decider로 Jev 말고 다른 모델도 넣을 수 있습니다.`
- 고친 예: `DM-15는 끝났고, 이제 d-means의 decider로 Jev 말고 다른 모델도 넣을 수 있습니다.`
- 참고: `~(으)로 맡았습니다`는 조사를 하나로 고쳐도 어색하므로 `~를 맡았습니다`로 씁니다.

### 7. 명사형 상투어 '~을 진행하다', '~에 해당하다'

동작을 명사로 바꾼 뒤 `진행하다`, `해당하다`, `수행하다`를 붙이면 공문서처럼 딱딱해집니다. 명사 속에 숨은 동사를 꺼내 씁니다.

- 원문 (judge, DM-27): `DM-22와 DM-25 미션이 preconquer-gogoymh 브랜치에 병합되어 채점 및 후속 티켓 정리를 진행해야 합니다.`
- 고친 예: `DM-22와 DM-25가 preconquer-gogoymh 브랜치에 병합되어 채점하고 후속 티켓을 정리해야 합니다.`
- 원문 (judge, DM-31): `채점과 후속 티켓 정리가 제 역할에 해당하고, 다른 누구도 이를 맡고 있지 않습니다.`
- 고친 예: `채점하고 후속 티켓을 정리하는 일이 제 역할이고, 아직 맡은 사람이 없습니다.`

### 8. '및'과 명사 나열

`A 및 B`, `#29 생성과 #26 통합`처럼 명사를 이어 붙이면 무엇을 했는지 동사가 사라집니다. `및`은 `와/과`나 `~하고`로 바꾸고, 한 일은 동사로 씁니다.

- 원문 (이슈 #26 제목): `DM-25 히어로 교체 재검토와 배너 부제 및 테스트 정리`
- 고친 예: `DM-25 히어로 교체를 다시 검토하고 배너 부제와 테스트를 정리하기`
- 원문 (채점 문서): `부족한 점은 #29 생성과 #26 통합으로 정리했고`
- 고친 예: `부족한 점은 #29를 새로 만들고 #26에 합쳐 정리했고`

### 9. 한자어 명사형 '누락 시', '~ 생성을 확인'

`~ 시`, `~ 생성`, `별도`, `중복` 같은 한자어 명사를 겹치면 보고서 말투가 됩니다. 조건은 `~면`으로, 결과는 주어와 동사로 풀어 씁니다.

- 원문 (채점 문서, DM-22): `241 KB 미리보기 PNG 생성을 확인했고, 배너를 다시 그리지 않으며 누락 시 실패합니다.`
- 고친 예: `241 KB 미리보기 PNG가 만들어지는 것을 확인했고, 배너를 다시 그리지 않으며 원본 PNG가 없으면 실패합니다.`
- 원문 (채점 문서, DM-22): `중복 --preview 인자를 별도 검사하지 않고 인자 오류 경로 테스트가 없습니다.`
- 고친 예: `--preview 인자가 두 번 들어와도 따로 검사하지 않고, 인자가 잘못됐을 때의 테스트도 없습니다.`

### 10. 한국어 메시지에 영어 섞기

한국어로 쓰는 메시지에 `done`, `is done` 같은 영어 상태 말이나 영어 문장을 섞지 않습니다. 화면에 보이는 작업 제목, 코드 식별자, 파일 이름만 원래 표기대로 둡니다.

- 원문 (judge, DM-31): `DM-28 미션이 preconquer-gogoymh에 병합되어 done이 되었으므로`
- 고친 예: `DM-28이 preconquer-gogoymh에 병합되어 끝났으므로`
- 원문 (Claude 4277, DM-20): `작업을 마쳤습니다 (작업: Drop Jev from imports and add Clef benchmark results): DM-20 is done: the README no longer imports Jev, and Clef's results are in the README.`
- 고친 예: `작업을 마쳤습니다 (작업: Drop Jev from imports and add Clef benchmark results). DM-20을 마쳤습니다. README 예제 코드에서 Jev import를 없애고 Clef 벤치마크 결과를 README에 넣었습니다.`

### 11. 피동 '반복되어 나타났습니다'와 붙어 버린 띄어쓰기

`~되어 나타나다`, `~되어지다`처럼 피동을 겹치지 않고 능동으로 씁니다. 파일 경로 앞의 띄어쓰기가 빠지지 않았는지도 봅니다.

- 원문 (polish, DM-28): `#general의 vanguard 메시지에서 영어 직역투와 종결어미 불일치가 반복되어 나타났습니다. 아직.claude/skills/polish/SKILL.md가 없으므로 이번 사례로 첫 윤문 스킬을 만듭니다.`
- 고친 예: `#general의 vanguard 메시지에 영어 직역투와 종결어미 불일치가 여러 번 나왔습니다. 아직 .claude/skills/polish/SKILL.md가 없으므로 이번 사례로 첫 윤문 스킬을 만듭니다.`
